## Codex第一次（8.1）

1. 總分：8.1／10

這已是內容完整、能形成中長期循環的農場 RPG，不只是美術展示或單線教學 Demo。最大差距不在功能數量，而是前期節奏、資訊密度、角色戲劇性與手機橫式排版。

2. 四項分數

- 內容：8.4／10  
  主線、每日目標、鄰居委託、好感故事、選擇回訪、具名訂單、料理、祭典及追光手冊彼此有串接，目標感很強。缺點是多數角色對話仍以教系統、交付獎勵為主，人物衝突與情感轉折偏薄。

- 風格：7.8／10  
  農場場景、建築、作物與暖色 UI 整體協調，新繪製的攤位、鍋子、選擇物件也有辨識度。扣分主要來自舊、新角色造型不一致、介面卡片過密，以及部分畫面同時出現太多框線、標籤與提示。

- 系統：8.2／10  
  任務卡、手札、訂單、升級、圖鑑與手機版導航的架構完整；照顧方式、折光、蓄光、曬乾、料理與祭典也有清楚的前後關係。手機橫式仍有明顯版面錯誤。長期經濟平衡、存檔穩定性、效能與觸控誤按率無法從靜態截圖驗證。

- 遊戲性：8.0／10  
  「現在收或等光」、「三種照顧方式」、「兩條生產路線」、「先招呼哪位客人」都是真正會改變結果的決定，回饋也很即時。問題是最初幾分鐘仍有太多照著任務卡按、等待倒數、閱讀重複說明的段落，玩家自主試驗的空間出現得稍晚。

3. 嚴重問題

- 第 13、98、107 張：手機橫式底部中央的「等光再收」操作卡，與右下角另一條相同提示互相重疊；右側文字還被畫面邊界截斷。這會直接造成「到底要按哪一個」的困惑，也明顯破壞完成度。相同操作只能保留一個入口，不能同時存在大型操作卡與被裁切的第二條提示。

4. 其他扣分點

- 第 75～78、91～100、104～107、127～128 張：同一步驟經常同時出現在任務卡、田上說明、倒數通知、底部操作卡與黑色提示條。按鈕雖然已收斂成一顆，但文字層仍重複，第一分鐘顯得比實際玩法複雜。

- 第 76、92、98、100、104～107 張：第一次收成的主要互動是按下按鈕後等待六至八秒。教學目的清楚，但作為最早期的核心體驗，玩家參與感偏低。

- 第 22、51、72～74、96、111、118～120 張：手機直式的手札、升級與圖鑑面板文字密度高、字級偏小。雖然有捲動提示，但閱讀負擔已接近管理型遊戲，不太像輕鬆農場 RPG。

- 第 17～18、20～21、25、65、67～68、84～85、96、113、119 張：卡片內再放卡片、卡片裡又分雙欄，框線層級過多。資訊大致找得到，但視線容易停在「讀表格」，而不是看農場與角色。

- 第 24、41、61、87～88、108、114、120、125 張：鎮長頭像戴禮帽、鬍子與服裝特徵鮮明，地圖小人卻仍是另一套舊造型。這是目前最顯眼的角色美術斷裂。

- 第 24、44、61～64、87～89、108～110、121～125 張：對話清楚、選擇也確實留下效果，但角色多半仍在說明規則、發任務或交代獎勵。從截圖看不到更強的矛盾、關係變化或需要玩家承擔代價的戲劇場面。

- 第 2、14、25、34、46、53～54 張：農田周圍有大面積同質草地，主要內容則集中在右下建築群。場景可讀性不差，但構圖稍空，農場逐步成長的視覺變化還不夠強。

5. 要到 8.5 分最該做的五件事

1. 重剪新存檔前兩分鐘  
   驗收標準：從開始到第一次收成不超過 60 秒；沒有超過三秒只能等待的空檔；同一時刻最多一個主要教學層；第一次收成後 30 秒內出現一個會改變資源或後續內容的選擇。

2. 讓角色選擇產生更深的故事後果  
   驗收標準：六個開場答案各自至少在後續章節觸發一段專屬場景，並包含一次有兩種結果的決定；結果除了每日獎勵或訂單，也要改變一段人物關係、對白或任務收尾，手札可回看。

3. 把三個中期設施做成真正的生產決策  
   驗收標準：蜂箱、香草小圃與餵食槽的兩條路線，各自至少連到一張專屬訂單、一項料理或一次祭典需求；切換路線前顯示下一批需求與機會成本，不能只看哪條產值較高就固定選到底。

4. 修完所有手機橫式主要流程  
   驗收標準：以 844×390 逐一重跑折光、等光、收成、照顧、手札、看火候及擺攤；不得有重複 CTA、被裁切文字或互相覆蓋的提示；主要按鈕完整可見，觸控區至少 44×44 px，田格與倒數仍能同時看見。

5. 統一角色美術並降低介面噪音  
   驗收標準：換掉鎮長舊地圖小人，使禮帽、鬍子、服裝輪廓與頭像一致；手機面板正文至少維持可讀字級；同一操作只保留一處完整說明；資訊面板最多兩層框線，刪掉重複的田上標籤、提示條與任務卡文字。

## Codex第二次（8.1）

1. 總分：8.1／10

完成度已高於一般網頁農場原型，具備可辨識的核心玩法、完整中期循環與手機版。主要差距不是內容量，而是故事張力、策略整合、資訊密度與少數響應式破版。

2. 四項分數

- 內容：8.2／10  
  主線、每日目標、鄰居委託、選擇後果、料理、祭典與好感故事相當完整。選擇能改變地圖物件、每日收益及具名訂單，是明顯優點。但目前可見對白多半服務教學與系統解說，角色衝突、懸念及章節高潮仍偏弱。

- 風格：8.0／10  
  色調、像素農場、面板框線及新繪設施大致統一，辨識度也足夠。扣分主要來自新舊人物素材落差、地圖空地及矩形拼接感，以及大量米色面板長時間遮住像素場景。

- 系統：8.2／10  
  種植、光照、照顧方式、乾燥、料理、訂單、升級、鄰居選擇及祭典能形成經濟鏈；桌面與手機直式整體可用。缺點是面板層級多、說明文字密集，手機橫式仍有明顯破版。

- 遊戲性：8.1／10  
  第一分鐘已有折光、等光收成與第二輪取捨，回饋清楚；中期另有看火候、設施生產、評比與擺攤。問題是可見互動仍大量依賴倒數、按鈕和說明卡，農地上的即時操作感與章節戲劇推力還不夠強。

未因你已註明的截圖準備狀態不一致扣分。音效、動畫流暢度、效能、存檔可靠度及長期經濟平衡在截圖中看不到，無法評分。

3. 嚴重問題

- 第 13、98、107 張：手機橫式的「等光再收」說明卡橫跨畫面中央，右側另有一條重複且被截斷的文字白條。上方任務卡、中央等待卡及下方工具列同時出現，目標田格遭大幅遮擋，屬於明顯響應式破版。

- 第 121、125 張：旁白或好感對話開啟時，左上任務卡仍保持展開並顯示主要按鈕；畫面同時存在兩個看似可操作的主入口，破壞「一次一個主要互動層」的規則，容易讓玩家不知道應先處理哪一個。

4. 其他扣分點

- 第 3、34、75、128 張：雖然教學只要求一件事，但新玩家同時看到小地圖、七個底部功能、完整資源列、任務卡、田上標籤及多個 NPC，視覺上的學習負擔仍高。

- 第 7、18、25、28、62、72、85、96、111、118、119 張：手札與升級面板資訊量大，手機版尤其依賴小字、長段落及內部捲動。內容找得到，但不夠容易掃讀。

- 第 24、29、44、61、114、121、125 張：角色確實會記住選擇，但可見對白多半在交代任務、獎勵或過去事件；人物慾望、彼此矛盾及章節危機還不夠鮮明。

- 第 37、39、58～60、76、92、104～107 張：追光、曬架與料理都有機制，但視覺表現主要是倒數、進度條及按鈕。截圖中看不到更強的動態反應或操作張力。

- 第 2、16、27、55 張：地圖仍有大片均質草地、硬矩形區塊及建築周圍拼接感；內容豐富度已超過場景精緻度。

- 第 114、120 張：鎮長對話頭像戴禮帽、造型鮮明，但地圖小人仍是另一套舊造型，角色辨識出現斷裂。

- 第 6、18、21、38、57、119 張：停用項目的灰字與米色底對比偏低，快速掃描時不容易區分「尚未達成」「不可用」及一般補充文字。

- 第 2 張：三個中期設施已清楚出現在地圖上，但截圖沒有呈現兩條生產路線的切換介面，因此無法確認路線選擇是否好懂、是否真的形成決策。

5. 要到 8.5 分最該做的五件事

1. 把第一個十分鐘串成一段有衝突、有收束的短篇故事  
   驗收：玩家在十分鐘內看見祖母便箋提出的具體謎團、兩名鄰居互相衝突的需求、一次會改變地圖與訂單的選擇，最後以一段角色場景或事件收尾，而不是只停在「又解鎖一個面板」。

2. 讓「追光」成為持續規劃的核心，而不只是第一株作物的教學  
   驗收：同一畫面可看見未來三道光的落點或時程；至少三塊田能組成「照顧方式 × 光性 × 訂單期限」的不同有效策略；玩家在不開手札的情況下能說明自己為何折光到某一格。

3. 把三個中期設施的雙路線做成真正可見的生產決策  
   驗收：點設施後直接看到兩條路線的原料、產物、時間、下一個用途與切換代價；切換後建築外觀或地圖標籤同步改變；每條路線在接下來十分鐘內至少能供應一張訂單、一道料理或一項祭典需求。

4. 完成手機互動層的響應式整頓  
   驗收：390×844及844×390下，同一動作只出現一顆主按鈕；修除第98、107張的重複截斷白條；選中的田格至少保留24px可視邊界；所有主要點擊區不小於44px；對話開啟時任務卡自動收成單列。

5. 做一次角色與地圖美術統一  
   驗收：替換鎮長舊地圖小人，使服裝、帽子及輪廓與頭像一致；統一新舊 NPC 的像素密度、描邊、陰影方向與比例；修掉主要建築周圍的硬矩形地表接縫，並讓桌面、手機各抽查十個場景都不再出現明顯素材世代差。

## MUSE（7.3）

## 1. 總分

**7.3／10**

系統數量與內容企圖明顯高於一般網頁小品，但目前主要問題不是內容不足，而是**同時要玩家讀、等、選、趕時間的資訊太多**。桌面版已接近可長期遊玩的農場 RPG，手機直式與前幾分鐘的引導仍明顯拖分。

## 2. 四項分數

| 項目 | 分數 | 判斷 |
|---|---:|---|
| 內容 | 7.8 | 主線、手札、鄰居委託、好感故事、每日選擇、收穫祭與具名訂單都有內容，不是只有種田循環；但大量說明文字稀釋了故事與目標感。 |
| 風格 | 7.9 | 像素農場、建築、作物與暖色 UI 大致統一，畫面討喜；人物造型、面板樣式與部分新舊圖示仍有落差。 |
| 系統 | 7.0 | 種田、照顧、追光、曬架、料理、訂單、升級、擺攤、圖鑑已形成完整架構；但選單層級深、資訊密度過高，手機操作尤其吃力。 |
| 遊戲性 | 6.8 | 「折光、等光、在光裡收成」有辨識度，也有即時回饋；可惜前期教學與數字說明過多，擺攤與看火候又突然變成限時反應遊戲，節奏不穩。 |

截圖看不到音效、效能、存檔穩定性、實際操作延遲與長時間經濟平衡，因此這些部分不計分，也不推測。

## 3. 嚴重問題

### 3.1 手機直式畫面上層資訊嚴重擁擠，部分文字已接近不可讀

- 第 010、011、019、042、049、073、074、091～096 張：頂部同時塞入金幣、等級、背包、季節、木材、石材、地肥、陽光等多項資源，字級極小且容易截斷。
- 第 042、049、071 張：看火候與料理成果面板幾乎佔滿手機寬度，背後農場完全失去作用，玩家只能盯著面板操作。
- 第 073 張：擺攤開場面板同時列出規則、星等、代幣、替代品、貨量與加減按鈕，直式畫面需要大量捲動，第一眼看不到「現在先做什麼」。

這會直接影響手機玩家判斷資源、找按鈕與理解規則。

### 3.2 第一分鐘同時出現太多層提示，玩家仍要自己找「唯一入口」

- 第 003、034、075、097 張：左上任務卡、田上標籤、光的預告圈、右上倒數、底部工具列同時出現。
- 第 076、092、098、100 張：任務卡寫等光，田上又重複寫秒數、份數與陽光，底部還有狀態提示。即使實際可按的按鈕只有一顆，畫面仍像有三個地方要操作。
- 第 013、100 張：橫式與矮筆電畫面中，任務卡、倒數提示與田上標籤分散在畫面三個位置，視線需要來回跳。

問題不是按鈕真的重複，而是**說明重複出現三次**，使「只教一件事」在視覺上仍像同時教三件事。

### 3.3 擺攤叫賣的限時壓力與閱讀量不匹配

- 第 032、084、094 張：兩位客人同時出現，各自有類型、耐心秒數、需求、熱門加分與庫存狀態，玩家還要先點客人、再點貨。
- 第 084 張：趕時間客人只有約 6 秒，但商品卡還要讀「有貨、剩幾份、口味、是否熱門」。
- 第 065、073 張：開場規則包含星等、代幣、替代品、熱門品項、貨量調整與最高分，進入限時玩法前已經是一整頁說明。

這很容易造成誤點、漏客與「不是不會玩，而是來不及讀」，對休閒農場玩家尤其不友善。

### 3.4 手札與後續委託仍是文字牆，目標被埋在說明裡

- 第 062、085、089、111、123 張：右側面板同時放步驟、進度、每日效果、解鎖訂單、永久效果與「帶我去」，字小、段落長，必須捲動才看得完。
- 第 020、025、067、096 張：主線、農場小事、鄰居委託與第 4 章雙做法同時存在，玩家不容易判斷哪一項是今天最值得先做的事。
- 第 123 張：兩個決定的每日差別需要並排讀完一整面文字才理解，不像遊戲內的直覺回饋，更像規格說明書。

這會讓內容量變成閱讀負擔，而不是目標感。

### 3.5 看火候的顏色規則不直覺，失敗成本在截圖中看不清楚

- 第 039、058～060、071 張：十格火候條同時使用藍、黃、紅色區塊，還有「先大後小」中途換位與虛線預告。
- 第 039、042 張：玩家要同時看鍋子狀態、剩餘秒數、火候條與三顆操作按鈕。
- 截圖看不到燒焦、失敗或做出普通成果時實際損失多少時間與材料，因此無法確認這套小遊戲是否公平；只能確認規則閱讀門檻偏高。

### 3.6 地圖名牌與田上標籤仍會遮住操作對象

- 第 003、014、034、046、076 張：田上氣泡與作物標籤直接壓在田格、人物或相鄰田地上方，短時間內要讀的文字比田本身還醒目。
- 第 086、109、116、124 張：跟著選擇出現的地圖物件需要靠名牌辨認，物件本體與用途的連結仍不夠強。
- 第 127 張雖已避開任務卡，但「多 1 份／陽光 +2」仍是非常大的浮字，若連續收成，容易遮住下一格操作位置。

## 4. 其他扣分點

- **美術一致性未完全收尾：**第 114、120、125 張的鎮長頭像已統一，但說明也指出地圖小人仍是舊造型；從第 081、114 張並看，人物頭像與地圖人物的辨識連結仍弱。

## 5. 要到 8.5 分最該做的五件事

### 第一優先：把第一分鐘真正改成「一次只學一個動作」

具體改動：新存檔前 90 秒只保留「種下 → 折光 → 等光 → 在光裡收成」四步；任務卡、田上標籤、底部提示三者只留一處顯示秒數與收益，其餘兩處只顯示箭頭或狀態圖示。訂單、手札、升級與照顧方式不得在第一次收成前跳出或要求閱讀。

可驗收標準：找 10 位沒玩過的玩家實測，至少 9 位能在不看額外說明下完成第一次光裡收成，且能說出「等光多拿到什麼」。

### 第二優先：重做擺攤叫賣的操作節奏，讓選擇先於反應速度

具體改動：選客人後暫停另一位客人的耐心消耗，或把前期客人耐心提高到至少 15 秒；商品只顯示圖示、剩量與「熱門」標記，口味與替代規則改在點到缺貨時才出現。第一場只出現一位客人，第二場才開放雙客人。

可驗收標準：新玩家第一場至少能完成 80% 訂單，且結算畫面能用一句話指出漏客原因，例如「第二位客人等太久」，而不是只給總分。

### 第三優先：把手札改成「現在做、今天可做、以後再說」三層

具體改動：手札第一屏只顯示目前主線下一步、今天最推薦的一件委託，以及一個「帶我去」按鈕；每日效果、永久加成、具名訂單全文全部收進第二層。每一條委託在第一屏最多兩行：去哪裡、做什麼、拿什麼。

可驗收標準：玩家打開手札 5 秒內能回答「我現在要去哪裡、找誰、做什麼」；手機直式第一屏不需捲動就能看到下一步。

### 第四優先：為手機直式做獨立資訊架構，不要只是縮小桌面版

具體改動：頂部資源列只常駐金幣、等級與陽光，其餘收進可展開列；底部主要按鈕高度與字級提高，任務卡固定只佔上方約四分之一。看火候、擺攤與料理成果改成全螢幕流程，步驟之間不要同時露出背後地圖。

可驗收標準：在 390×844 下，所有主要按鈕與數字不截字、不小於易讀範圍，且看火候與擺攤進行中不需要橫向或縱向捲動面板。

### 第五優先：讓選擇的後果先被「看到」，再被「讀到」

具體改動：每個開場選擇完成後 60 秒內，必須在地圖上出現可互動的新物件、NPC 新對白與第一張具名訂單；手札只補一句结果，不要先給整頁對照表。兩種決定的差別改用物件外觀、每日可領取物與 NPC 一句話呈現，文字對照表移到玩家實際領過一次效果後再解鎖。

可驗收標準：玩家做完決定後，不打開手札也能指出農場哪裡變了、每天多了什麼；第 108、109、116、122、123 張這條流程能在 90 秒內走完，且中途不需要閱讀超過三行連續文字。
