# 陽光農場 內容優化 R81 計畫（精簡版）

依據 R80 評審：Codex 8.1、8.1，MUSE 7.3，Claude 6.9（另一份 Claude 評審進行中）。使用者指示「不要過度稽核」：這一輪評審只用 Codex 一次＋Claude 一次，截圖只抽看改到的畫面，完整測試只在收尾跑一次。

## A 線（Codex）：數字說得通、擺攤先選再趕
1. 具名訂單金額：任何具名訂單（含做完決定後的第一張）給的金幣，不得低於畫面上同樣東西的一般訂單（例：一般訂單 2 份小麥 14 金，具名單至少 14 金，卡片寫的「多幾成」要跟實際入帳一致）。
2. 照顧方式三行改寫成絕對時間：「約 N 秒（比勤澆水慢 M 秒）」，拿掉看不到基準的百分比；三行秒數在桌面、手機直式、橫式一致。
3. 擺攤：第一場只來一位客人、耐心至少 15 秒，第二場起才兩位；商品卡只放圖示、剩量、熱門標記，口味與替代品說明在缺貨時才出現；0 星結算給一句可照做的改法與小保底。
4. 測試：`scripts/test-content-r81-numbers.js`。

## B 線（Codex）：第一分鐘一處說明、手機橫式不重複
1. 同一時刻只在一處寫秒數與收益（田邊動作列）；任務卡只留一句狀態，田上標籤只留一行名稱；拿掉底部「按了會等 N 秒」那條重複說明。
2. 手機橫式（844×390）：等光、折光、收成時不得出現重複或被截斷的操作條（R80 圖 13、98、107）。
3. 手機右下大鈕跟著作物狀態：沒熟不得寫「收成」。
4. 開場便箋與實際教學順序一致；「下一步」不得指向已完成的事（R80 圖 81）。
5. 測試：`scripts/test-content-r81-first.js`、`scripts/test-content-r81-first-layout.js`（四尺寸）。

## C 線（Claude 子代理）：前十分鐘有一段有衝突、有收尾的小故事
1. 新存檔十分鐘內：祖母便箋留一個具體的謎（例如籃底的舊種子是誰留的），兩位鄰居對同一件事有相反的需要，玩家的選擇改變地圖物件與一張具名訂單，最後用一段角色場景收尾（對話裡有情緒變化，不是交代規則）。
2. 鄰居對白減少「說明規則／交代獎勵」的句子，改由角色的立場與情緒說出來；規則說明留給任務卡與按鈕。
3. 手札第一屏分三層：現在做（一行＋帶我去）、今天可做（最多兩項）、以後再說（收合）。
4. 測試：`scripts/test-content-r81-story.js`。
