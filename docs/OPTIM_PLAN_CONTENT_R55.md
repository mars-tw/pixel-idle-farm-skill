# 陽光農場 R55 優化計畫：手機操作重做、即時回饋、前期資訊減量

版本 **0.1.78**／`content-r55-20261109-1`，基準 R54（`aa7e61a`）。

## 目標調整
使用者決定改以「三方平均 8.5」為達標標準。R41～R54 三方平均約 7.7（Codex 8.0～8.2、MUSE 7.1～7.9、Claude 7.2～7.8）。
最低的兩項一直是「系統」（6.5～7.3）與「遊戲性」（6.9～7.4），扣分集中在：
- 手機版操作太擠：七個工具擠一列、頂部欄滿版、長面板沒有捲動提示、橫式種子卡被切。
- 前期大量「看得到不能用」：市集未開放就攤開三張訂單、升級與建造幾乎全買不起、建造一打開就是死路。
- 操作後的回饋不夠：收成、交付、升級後看不到「得到什麼」飛向哪裡。
- 共用小麥的訂單數字讓人要自己算。

## A 線：系統、回饋與前期節奏（派 Codex）
1. **共用作物訂單寫成算式**：每張訂單顯示「需要 X・可用 Y」；被前一張占用時寫「庫存 4－前單 4＝可用 0，還差 2」。不再出現兩張都寫「持有 4」。
   - 驗收：單元測試持有 4、訂單 4＋2 時，兩張卡的文字與交付按鈕狀態一致。
2. **即時回饋**：收成時，田格上方跳出「小麥 +2」，右上背包數字放大閃一下；交付訂單與升級時，跳出「+N 金」，金幣欄同步閃一下。降低動態模式時只閃數字，不做位移。
   - 驗收：單元測試收成、交付、升級三種事件都會產生回饋資料；CSS 有 `prefers-reduced-motion` 分支。
3. **前期資訊減量**：
   - 市集未開放時，預告只顯示一張範例訂單和解鎖條件，其餘寫「開放後還有 2 張」。
   - 第一章完成前，升級面板只完整顯示「下一個買得到的」一項，其餘收進「之後的目標」摺疊區。
   - 驗收：單元測試與字串。舊測試若規定預告要有三張卡，可同步，但「預告與開放後第一批相同」的意圖必須保留（資料仍是三張）。
4. **建造不再一打開就是死路**：新存檔走到第一次打開建造時，至少一項建物買得起。可以把堆肥場第一級降到 12 金，或在建造提示寫出「再收成一次就買得起」並附前往按鈕。
   - 驗收：單元測試新存檔照主線走到交付老農班伯時，`canBuild` 至少一項為真。
5. **任務卡只回答「現在做什麼」**：展開的任務卡只保留一個目前步驟、一個進度數字、一個主要按鈕；章節「本章已交付 X/3」移到故事手記。
   - 規則變更：R26 規定收合摘要要保留章節進度。這條改成保留目前步驟與進度，並在回報中說明。
   - 驗收：單元與版面。

## B 線：手機操作重做（派 MUSE）
6. **手機底部工具列減為五格**：手、澆水、建造、日誌、更多；清除與查看移進「更多」。每格寬度至少 56px，文字至少 12px。
   - 驗收：390×844 量測五格寬度與字級；「更多」裡可以找到清除與查看。
7. **手機頂部欄精簡**：標誌縮小並完整顯示，金幣、等級、背包、材料一列排得下，不超出畫面。844×390 時，右上種子卡的名稱、價格與「全部」完整顯示。
   - 驗收：量測每個 HUD 元素都在可視範圍內，文字沒有被截斷（`scrollWidth <= clientWidth`）。
8. **長面板捲動提示**：手機面板內容超出時，底部顯示漸層加「往下還有」小箭頭；捲到底後消失。不得與「再顯示 N 項」同時出現（R36 規則）。
   - 驗收：量測。
9. **手機橫式可玩區**：工具列高度降到 52px 以內，互動鈕不蓋任何田格、NPC、建物，中央可操作區 ≥ 畫面高度 55%。
   - 驗收：量測。
10. **對話頭像統一像素顆粒**：鎮長、祖母頭像用 CSS `image-rendering: pixelated` 搭配整數倍縮放顯示，和遊戲內角色同一種顆粒；不新增生成圖。
    - 驗收：截圖目視、CSS 規則存在。
