# 陽光農場 內容優化 R85 計畫

依據 R84 評審：Claude 7.1（內容 7.6、風格 7.3、系統 6.6、遊戲性 7.0）、MUSE 7.8（`REVIEW_CONTENT_R84.md`），目標 8.5。R84 後依使用者指示暫停優化、改送 App Store 1.0.1 第 11 版；送審已完成（等待審查），本輪恢復。全部只做本機提交，不推送，不影響審查中的版本。

最拖分的是「系統」：同一個畫面講兩件事、兩顆主按鈕、要做的東西不在畫面上。使用者也說過「應該增加遊戲內容，而不是一直修按鈕大小」，所以 B 線加一段新玩法。評審仍只送兩位，完整測試只在收尾跑一次。

## A 線：一個下一步、一顆主按鈕、目標在畫面內（R84 未解 1、2、3、5、9）
1. 下一步只有一個來源：任務卡標題、任務卡按鈕、手札「現在做」、手機右下大鈕講同一件事（R84 圖 75、34、52、129：標題「找鎮長葛瑞交談 0/1」按鈕卻是折光）；手札章節進度與子項數一致（圖 136、147：0/1 卻列兩個子項）。
2. 同一動作只留一顆主按鈕：任務卡與右下大鈕不寫同一句（圖 95、128、160），也不出現第三個動作（圖 19）；任務卡上能按的東西看得出是按鈕（圖 46、48、50、53、77、82、92、132）；祭典任務卡文字與按鈕一致（圖 32、65、101）。
3. 要做的目標在畫面內：按下一步時鏡頭帶到目標、目標不被卡片蓋住；手機在光裡收成後田不離開畫面（圖 93）、早市取捨田不被切在左緣（圖 103）、大鈕不指向畫面外（圖 133、161）、展開的祖母手記卡不蓋住要看的田（圖 158、159、162）。
4. 844×390 第一枚印章小卡不與祖母來信提示重疊（`test-content-r76-sunbook-layout.js` 偶發失敗的原因），修好後該測試連跑 5 次全過。
5. 測試：`scripts/test-content-r85-one-step.js`（規則＋四尺寸量測）；不得放寬既有門檻。

## B 線：看得懂的光、不空等、雨天也有事做（R84 未解 4、6、7 ＋新玩法）
1. 折光前看得到「折過來會怎樣」：瞄準時預覽落點與這格作物的光性、收益（圖 53、70、36）；同一時間只有一個預告圈（圖 11、16）；同一格田不疊多個教學元素（圖 31、69、99）。
2. 等待：查出矮筆電 29 秒等光的原因（圖 106），讓新存檔前十分鐘兩道光最多隔 20 秒在所有尺寸都成立。
3. 手機閱讀量：手機版同一畫面的說明字數減少（MUSE 點名圖 22、42、69～74、94、137），細節收進可展開處；手機麻雀二選一要確實跳出（圖 163，先查是截圖等待不足還是真的沒跳）。
4. **新玩法：雨天也有事做**。現在雨、雪、霧、暴風雨不出光斑，招牌玩法在壞天氣整段停擺。加一個壞天氣專屬、和陽光相關的小玩法（例如雨天在田邊接雨水、雨停後出現一次較大的「雨後虹光」，或霧天點燈引路），要能在新存檔前 30 分鐘內遇到、有明確獎勵、不打斷主線、離線不累積。新圖由 B 線列需求、主控請 MUSE 畫。
5. 測試：`scripts/test-content-r85-light.js`、`scripts/test-content-r85-weather.js`。

## C 線：美術與評審截圖工具（R84 未解 8）
1. 兩種種子籃縮圖在 64px 分得出來（圖 109、116）；藍布老麥田故事階段與分支階段同一套畫法（圖 140、145 vs 148～150）；不同料理不共用爐子圖示（圖 21、57）；風吹白線不畫在介面上（圖 32、82、83）。新圖用 MUSE 畫（洋紅底去背、裁切、manifest 寫實際模型），不得用程序化方塊頂替。
2. 把評審截圖做成 repo 內可重跑的工具 `scripts/review-capture-r85.cjs`：新存檔第一分鐘、田的各階段、田邊小事、舊麥種故事與兩條分支、祖母手記、早市、祭典、料理、手札、地圖；1366×768、1366×600、390×844、844×390 四尺寸；輸出到指定資料夾並附每張圖的說明清單。之後每輪評審都用它，不再依賴暫存區腳本。
3. 測試：圖片資產檢查（尺寸、透明、manifest）＋截圖工具在四尺寸各跑一次不報錯。
