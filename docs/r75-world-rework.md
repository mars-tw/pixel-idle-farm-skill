# 陽光農場 R75 重製規格與交付紀錄

版本：`r75-20261002-2`。專案全名：阿軒割割陽光農場開源遊戲世界。

本文件保留 R75 當輪的交付狀態。專用釣台與餐桌已在後續 R76 完成，最新素材、遷移修正與來源請見 [R76 紀錄](r76-art-release.md)。

## 重製起點

實際試玩 R74 新存檔，桌機 1440×900、手機 390×844。手機預設 fit 將 22×12 世界縮成 14px 圖磚，主角與農地難以辨認，畫面還留了大量空白。桌機同時呈現工具、全寬任務列、助手和常駐側欄，農場變成操作介面的背景。舊任務主要教操作，作物、人物、探索和動物沒有共同的目的。

R75 的主循環是：在田裡準備食材，帶去找居民，修復河畔，做料理和釣魚，再把收穫帶回居民生活。放置收益維持原有時間差結算，主動遊玩則提供不同的行動和故事結果。

## 遊玩安排

下列時間是設計目標，不是假稱已取得真人留存數據。

| 階段 | 玩家要做的事 | 選擇與結果 | 目標時間 |
|---|---|---|---|
| 回家 | 接下祖母留下的農場，走近葛瑞 | 不先塞入長篇操作說明；地圖上的人是故事入口 | 0–1 分鐘 |
| 田醒了 | 種三格小麥、澆三格水 | 澆水縮短等待；待長成時可探路或照顧雞 | 1–3 分鐘 |
| 第一餐 | 收六份作物，給班伯兩份小麥，回農舍烤麥餅 | 收成有去處；交付會消耗物品並留下完成紀錄 | 3–5 分鐘 |
| 河畔復興 | 修釣台、釣魚、湊材料修橋、採薄荷 | 可清障取得材料，也可用訂單收益向市集補料 | 5–12 分鐘 |
| 收穫野餐 | 修餐桌，照顧動物、交訂單、整理花園、做兩種料理 | 修復物件改變地圖，居民在結局後聚到河邊 | 12–25 分鐘 |
| 自由經營 | 五分鐘一批的河畔餐籃委託、四季作物、動物品質和農場升級 | 魚與料理不在主線結束後失去用途；建材可再取得 | 持續遊玩 |

進度依成功事件與可證明的既有狀態累積。先播種、先收成、先交談，也能在任務開放後被承認。`ready` 保留已達成的歷史條件；實際交付仍重查現有物品。獎勵只發一次，失敗時不扣任何一部分資源。

## 畫面與操作

- 主場景是完整視口，預設 natural 相機；手機圖磚至少 64px，不再預設縮成整圖。
- 常駐內容只留名稱、資源、短任務、種子和工具。訂單、升級、手札、圖鑑按需要展開。
- 地面不畫格線，移除每格 padding、鎖頭和封鎖斜紋。選取目標可顯示單一輪廓。
- 步道改成連接設施的支路，移除繞農場一圈的方形道路。
- 相機周邊有同圖集的草地延伸，讓靠近地圖邊緣時，主角仍能留在可操作位置。延伸是鏡頭背景，不能當成新增可探索區。
- 桌機保留點地圖與 WASD。手機保留 D-pad、A 鍵和地圖動作列。工具是具名的原生按鈕。
- 角色走路與農務使用逐幀圖集，改以 requestAnimationFrame 更新。農務在動作約 430ms 的作用階段結算；中途換目標會取消未結算的行動。
- 新的料理、交付、修復、交易、動物照護，都先尋路到相鄰位置再執行。對話框開啟時，背景維持 inert。

## 素材使用契約

本輪沿用已存在的原創人物與 PNG 圖集。額外兩張 `gpt-image-2` 素材實際送出後回傳 HTTP 401，未產生新圖，也沒有改用其他模型或把替代素材稱成新生圖。

| 地圖物件 | 本輪實際來源 | 精確渲染方式 | 後續專用美術需求 |
|---|---|---|---|
| 主角與鎮民 | v4 walk/actions/npcs | JSON frame x/y/w/h，3:4 角色比例與腳底錨點 | 保留既有角色身份，不重畫成另一個人 |
| 作物 | v4 crops/crops2/crops3/crops4 | 48×48 五階段 frame，無百分比裁切 | 有問題的品項逐株重製；不得再生成擁擠概念圖切片 |
| 釣台 | terrain `bridge_h` | 地圖位置 `t2_9`，寬 1.65 個圖磚 | 單物件 PNG，完整木板、柱腳、釣具架，周圍安全留白 |
| 野餐桌 | structures `market_stall` | 地圖位置 `t10_10`，寬 1.6 個圖磚 | 專用桌椅、餐籃、布巾；本輪沿用攤位 sprite，尚非專用餐桌美術 |
| 花園 | structures `flower_bed` | 地圖位置 `t6_2`，寬 1.15 個圖磚 | 可直接沿用，保留修復前後的辨識差異 |

交付專用圖時，一張圖只放一個物件。去背後取 alpha 的非透明 bbox，四邊保留至少 8 個原生像素，縮放採 nearest-neighbor，先確認腳底／底部錨點，再登錄 JSON。不要依生成圖片的名義網格猜測裁切，也不要把畫成棋盤格的 RGB 背景當成 alpha。

## 製作端接續要求

下一輪先拿手機與桌機各玩一個完整新存檔，記錄卡住、點不到、看不懂和等待無事可做的位置。任何新系統都要有場景入口、耗用／報酬、操作回饋、存檔規則與可執行驗證，不再只增加設定表或面板。

本輪獨立瀏覽器稽核先得到 346 通過／24 失敗，保留失敗而沒有改弱斷言。修正六類根因：320px 動作列遮擋、種子欄擋住 D-pad、頁籤最小寬度造成溢出、短視口 modal 裁切、Tab 焦點離開 modal，以及目標資訊缺關閉鈕。原測試重跑後 370／370 通過。四視口第一章三任務皆透過真 UI 完成；後段是明確命名的修復／釣魚／料理／交易 fixture，完整三章資源流程另由純邏輯測試驗證，兩者不可混稱。

優先補專用餐桌／釣台和四向持竿動作；再做一段可走進去的農舍室內、居民日程與帶分支的節慶。這些都不列為本輪已完成。新增地區前，先確認目前三章玩家能自己走完，且主線結束後的料理、釣魚和動物仍有可交付的用途。
