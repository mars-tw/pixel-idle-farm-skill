## Codex（gpt-5.6-sol）第一次：8.1

1. 總分：8.1／10

完成度已達可公開測試的水準。核心辨識度來自「追光、折光、蓄光、曬製、火候」這條生產鏈，加上會永久改變農場的角色選擇。主要差距不在內容數量，而在部分玩法仍偏向照任務卡點擊，以及規則回饋尚有矛盾。

2. 四項分數

- 內容：8.5／10  
  主線、每日事項、鄰居委託、好感故事、節慶、料理、選擇後續與永久場景變化，已形成完整的小鎮生活架構。文案大致清楚且有人情味。扣分在於截圖可見的角色故事仍偏短，多數內容透過任務清單呈現，戲劇張力與人物衝突深度看不到。

- 風格：8.3／10  
  地圖、建築、作物、設施、光斑與多數圖示有一致的暖色像素風；羊皮紙面板也很適合題材。桌面、矮筆電與手機直式整體都能維持辨識度。部分角色頭像的繪製精細度和風格不一致，資訊密集時也會壓過漂亮的農場畫面。

- 系統：7.9／10  
  任務卡、田邊狀態、升級卡、手札與下一步大致能互相對應；照顧、光照、乾貨、料理、訂單、節慶之間已有資源循環。主要扣分是擺攤星等規則出現可見矛盾，以及部分面板資訊過密。經濟平衡、長期進度速度與存檔穩定性無法從截圖確認。

- 遊戲性：7.8／10  
  收成大字、光照加成、料理成果、評比明細和選擇後果都有明確回饋；中後期活動也不少。第一分鐘雖然非常清楚，但大多仍是「按指定按鈕、等待幾秒、再按指定按鈕」，早期自主規劃感不足。

3. 嚴重問題

- 第 32、66 張，擺攤結算視窗：畫面寫明一星門檻是 50 分，但第 32 張以 49 分獲得一星，第 66 張甚至在「答對 3、漏掉 1」且只有 45 分時仍獲得一星。這會直接破壞玩家對計分與星等規則的信任。若另有「全答對保底一星」規則，第 66 張也不符合；必須把例外條件寫進門檻，或依門檻正確判星。

4. 其他扣分點

- 第 76、92、98、100 張：第一株小麥的選擇是「現在收 2 份」或「等約 7 秒收 3 份＋陽光 2」。畫面看不到立即收成的任何優勢，因此形式上有選擇，實際上答案過於明顯。
- 第 75～78、91～93 張：第一分鐘的導引清楚，但操作幾乎全由任務卡指定，玩家尚未真正判斷田格、作物或光線配置。
- 第 97～99 張：手機橫式的上方任務列、HUD與下方工具列占掉大量高度；第 99 張照顧面板又覆蓋主要田區，可操作但非常擁擠。
- 第 72～74、94、96 張：手機直式的手札、追光手冊及第 4 章任務資訊密度偏高，需要長距離捲動；重要選項與說明容易混在同一層級。
- 第 82 張：同時出現換季、本季小事、祖母來信、集章卡與任務卡。即使是準備狀態，也證明大量事件同時觸發時仍會形成提示堆疊。
- 第 44 張：老農班伯的半寫實頭像，與像素世界及第 24、29 張較卡通化的角色頭像有明顯風格落差。
- 第 79、82、83 張：「下一步」直接把玩家送到目標，操作便利，但若大量使用，地圖探索與「住在農場小鎮」的空間感會被任務導覽取代。
- 第 57～60 張：三種火性已有差異，但操作仍主要是反應條位置；從截圖看不到食材、料理種類或玩家選擇會如何改變操作策略。
- 第 47、51、68、74 張：追光手冊的收集目標清楚，但各作物都是相同四枚印章結構，容易變成重複填表，作物個性仍可再加強。

5. 要到 8.5 分最該做的五件事

1. 讓第一個收成抉擇真的有取捨  
   驗收標準：立即收成必須提供畫面可見的獨立利益，例如趕上限時訂單、先推進劇情或保住下一道光；等待則獲得較多作物與陽光。兩條路都能完成教學，後續任務文字與回饋必須不同，不能只存在一個數學上明顯較好的答案。

2. 在第一個五分鐘加入一個由玩家規劃的追光小局面  
   驗收標準：提供至少三格田、兩道可預見的光與兩種光性不同的作物；玩家必須自行決定種哪裡、折哪一道光、何時收成。至少要有兩種能成功的策略，任務卡只講目標，不逐步指定答案。

3. 把「選擇改變世界」提早變成第一段情感鉤子  
   驗收標準：第一次收成後五分鐘內，完成一段三至五句的角色事件與二選一；選完立即改變一句對白、一個地圖物件及一項後續互動。玩家不開手札也能看懂自己造成了什麼改變。

4. 統一擺攤計分、門檻與結算  
   驗收標準：所有結算以同一函式判定星等；45、49、50、120、200 分建立邊界測試。若有保底星等，開場規則與結算必須明寫觸發原因；逐客對帳加總必須等於總分。

5. 重排手機橫式與大量事件的互動層  
   驗收標準：844×390 時，任務列可再縮成單行，田邊選單改為不超過畫面高度 35％的橫向面板，目標田格與主要按鈕不得被遮住；多事件同時發生時只顯示一張提示卡，其餘進入可展開佇列。

## Codex（gpt-5.6-sol）第二次：8.1

1. 總分：8.1／10

已具備可玩的完整產品輪廓，不只是農場介面展示。折光、照顧方式、加工、料理、訂單、鄰居選擇、收穫祭與手機版皆有實際操作畫面。主要差距在於資訊層級、部分規則說明，以及中長期選擇是否真的形成不同玩法。

依題目說明，由截圖準備造成的等級、章節與資源不一致不扣分。音效、動畫流暢度、載入速度、存檔可靠度、長期經濟平衡與實際觸控誤觸率，截圖無法驗證。

2. 四項分數

- 內容：8.0／10  
  有清楚主線、每日任務、鄰居委託、好感故事、開場選擇回訪與永久場景變化（圖 24、29、41、44～45、61～64、85～89）。文案普遍能直接說明目標與後果。不過目前看見的劇情多為功能型短對白，還不足以確認完整章節是否有真正的情緒高潮、角色衝突與收束。

- 風格：8.5／10  
  場景、建築、設施、作物和季節效果的像素美術一致且辨識度高，桌面與手機都保有遊戲感（圖 2、16、27、37、54、82）。米色紙張、棕色描邊及黃色主按鈕已形成穩定的 UI 語言。扣分主要來自通知層過多，以及少數面板的文字密度破壞畫面精緻感。

- 系統：7.9／10  
  任務、訂單、升級、圖鑑、料理、加工、好感、建造與活動的架構相當完整；桌面、矮筆電、手機直式與橫式也都有對應排版。問題是部分規則未在結果畫面自洽、長面板資訊密度高，截圖也無法證明經濟與後期進度是否平衡。

- 遊戲性：8.0／10  
  R78 的第一分鐘明顯比舊版集中：種植、折光、等待或立即收成、光裡收成回饋形成完整的小循環（圖 75～78、91～93、97～100）。照顧、乾燥、火候、擺攤和祭典提供了變化。不過大量操作仍由任務卡直接帶路，容易形成「照著黃色按鈕跑流程」，自主探索與策略差異還可以更強。

3. 嚴重問題

- 圖 33、66：星等顯示與門檻表面矛盾。畫面寫一星門檻為 50 分，但 49 分與 45 分都顯示一星；結算沒有說明這是「全數正確／無漏客保底一星」，玩家會直接懷疑計分錯誤。必須在星星旁明列保底原因。

- 圖 82：同時出現換季訊息、本季小事、祖母來信、追光手冊集章卡、任務卡及資源狀態，與「一次只留一個主要互動層」的設計目標不符。玩家無法判斷應先處理哪一項，也明顯遮蔽農場畫面。圖 23、46也有較輕微的同類情況。

4. 其他扣分點

- 圖 75、91、97：任務卡已有「把光折過來」，田邊又出現相同用途的「把光折到這裡」，實際仍有兩個主操作入口。對新手雖有幫助，但會削弱介面層級。

- 圖 62～64、72、74、85～89、96：手札內文偏密。手機版尤其需要長距離捲動，章節做法甲／乙仍維持雙欄，閱讀與比較成本偏高。

- 圖 65、73：擺攤開場資訊很多，固定的「開始叫賣」按鈕占據底部空間，下方商品是否完整可捲動，單憑截圖看不出來。即使能捲動，也缺少明顯提示。

- 圖 79：「新的作物與農場能力」過於籠統。里程碑卡應像圖 16、46一樣直接列出作物、能力與數值。

- 圖 47、51、68、74：追光手冊的印章概念清楚，但一屏同時放作物、四種印章、進度與獎勵，手機版第一眼較像成就清單，未立即說明印章將如何改變種田策略。

- 圖 25、67、96：第 4 章雙路線有差異，但主要仍以素材清單和報酬呈現，缺少更具故事性的後果描述，選擇容易退化成「哪邊材料比較便宜」。

- 圖 1、24、29、44：人物頭像是較細緻的插畫風，世界人物則是像素風；整體尚能共存，但美術語彙並非完全一致。

5. 要到 8.5 分最該做的五件事

1. 把六個開場選擇都發展成真正不同的遊玩路線  
   每條至少包含：當場不同反應、一個地圖永久變化、一個結果不同的後續決定、一項每日主動互動，以及後續章節至少兩次角色回應。驗收時從六個新存檔各走一條，手札、地圖、獎勵與後續對白都能看出差異，不能只換文案或擺設。

2. 讓作物形成不同策略，而不是共用同一套最佳解  
   至少四種作物各自設計一條不同優勢路線，完整連動照顧方式、光性、乾燥／料理、市集熱門與祭典評分。驗收標準是同一天的需求條件改變後，最佳種植與加工選擇也會改變；不能永遠都是固定選勤澆水或固定等光收成。

3. 修正擺攤計分的可理解性並增加決策回饋  
   結算逐位顯示「需求、交付、基本分、熱門加分、連續答對、代幣、合計」，若未達 50 分卻因保底得到一星，星星旁必須明寫原因。用固定的三局測試資料驗收，畫面加總、總分與星等必須完全一致。

4. 建立真正的單一通知佇列  
   同時間最多只允許一個阻斷面板、一張非阻斷提示卡與一則短暫提示；其餘排隊。以圖 82 的換季、祖母來信、本季小事、集章及任務更新同時發生為驗收案例，必須依序出現，且不遮住目前要操作的田格。

5. 重排手機版長內容與操作層級  
   在 390×844 與 844×390 驗收：主要按鈕、關閉鍵與目前進度始終可見；第 4 章甲／乙改成上下卡片或分頁；所有觸控目標至少 44×44；擺攤商品均可看見或有明確捲動提示；照顧彈窗開啟時仍能看見目標田格。
