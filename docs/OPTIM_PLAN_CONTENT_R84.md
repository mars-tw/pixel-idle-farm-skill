# 陽光農場 內容優化 R84 計畫（精簡版）

依據 R83 評審：Claude 6.7、MUSE 7.2（`REVIEW_CONTENT_R83.md`）。評審一再抓到「同一張任務卡在某個狀態破版」，每輪只修到被點名的那一種。這一輪改成用自動掃描把任務卡所有狀態一次掃乾淨，再處理下一步矛盾、一次只有一層視窗與前幾分鐘的節奏。評審仍只送兩位，完整測試只在收尾跑一次。

## A 線：任務卡全狀態掃描（四尺寸 × 展開／收合 × 全部下一步）
1. 建一支掃描測試：列舉所有會出現在任務卡的下一步（主線各步、今日三件事、第一餐選路線、祖母手記各步、舊麥種故事各階段、兩條分支各階段、早市取捨、等光、折光、收穫祭、第 4 章雙做法），每個狀態在 1366×768、1366×600、390×844、844×390 各量展開與收合：卡內所有文字框與所有按鈕框兩兩不重疊、按鈕文字不被裁切、「收合／展開」鈕不蓋主按鈕、收合時一定顯示至少 4 個字的短句（不能只剩按鈕或 1/3）。
2. 把掃描抓到的所有破版修掉，包含 R83 圖 76、104、129（展開時「等光再收」壓住說明）、圖 72 等（手機收合左邊空白）、圖 12、17、18、20、152（收合鈕蓋住主按鈕）。
3. 不得放寬任何既有版面門檻；任務卡高度維持原本上限。
4. 測試：`scripts/test-content-r84-card-sweep.js`。

## B 線：下一步不矛盾、一次只有一層
1. 任務卡、手札「現在做」、章節清單、地圖驚嘆號講同一件事、同一個數字（R83 圖 77、96、152）；任務卡不得指向地圖上還不存在的物件（圖 138、139）；封存路線全程不出現「藍布老麥田」（圖 144）；拿掉「Lv 3 才解鎖，現在就能種」這類自相矛盾句（圖 87、111）；同一張合作單份數一致（圖 87、89）。
2. 一次只留一個主要互動層：對話、手札、結算、集章卡不同時出現（圖 29、147）；提示與結算卡不壓任務卡（圖 106、134）；同一枚印章只跳一次（圖 19、23）；看火候開啟時灶台清單退場，只留一個關閉鈕（MUSE：圖 39、58、71）。
3. 手機右下大鈕：作物沒熟不寫收成（圖 128）；任務帶路時不寫無關物件（圖 153 仍有）；「另一件」改成說得出要做什麼的字（圖 160）。
4. 測試：`scripts/test-content-r84-consistency.js`（規則）＋必要的版面檢查。

## C 線：前幾分鐘的節奏與舊麥種成果
1. 同一畫面「等光再收」最多出現一次（動作列放秒數與收益，其他地方只寫狀態）（圖 11、105、130）。
2. 沒有道具時，前十分鐘下一道光的等待不超過 30 秒（圖 37 曾是 86 秒）；用遊戲時鐘測。
3. 田邊小事在 64px 縮圖認得出來：圖顯示放大到至少 40px、加短名牌（「撿落穗」等）常駐顯示（圖 159、161）。
4. 藍布老麥田至少佔 2×2 格的視覺範圍，四個階段外形明顯不同：照過 1 次光時還是青綠色、成熟才金黃發光（需要的新圖由主控請 MUSE 畫，先接路徑與後備）。
5. 鎮誌舊物出現當下鏡頭帶過去、小地圖有標記；三樣找齊後的擺飾至少跟告示牌一樣大。
6. 測試：`scripts/test-content-r84-pace.js`。
